# 测速与延迟诊断方法

> 原文地址：[https://claucc.net/articles/speed-test](https://claucc.net/articles/speed-test)　·　更多教程见 [claucc.net](https://claucc.net)

「慢」其实分很多种。先分清是延迟高、带宽小，还是某个网站单独慢，才能对症下药。

## 先理解：AI 使用其实不吃带宽

> ChatGPT / Claude 的流式输出峰值约 50KB/s，几十 Mbps 的带宽就富余上百倍。对 AI 账号来说，**住宅 IP 的「干净 + 稳定」远比峰值速度重要**。

| 项目 | 说明 |
| --- | --- |
| Claude / ChatGPT 流式输出 | ≈ 50 KB/s |
| 1080p 视频 | ≈ 5 Mbps(约 100×) |
| 结论 | 用 AI:稳定 > 峰值速度 |

*图:AI 几乎不吃带宽,几十 Mbps 就富余上百倍*

所以如果你只是用 Claude / Codex，不要被「测速数字不高」吓到——能稳定流式输出、不断流就够了。带宽大的需求主要是大文件下载、视频。

## 测延迟（最该看的指标）

```bash
# 测到目标站点的总耗时(秒),越小越好,多跑几次看是否稳定
curl -o /dev/null -s -w "%{time_total}
" https://claude.ai
0.42
curl -o /dev/null -s -w "%{time_total}
" https://chatgpt.com
0.38
```

多跑几次看是否稳定。偶尔一次高没关系，**持续高或忽高忽低**才是问题。

## 测网页实际体验

- 浏览器开 fast.com / speedtest.net 看下载带宽（注意：走住宅 IP 时数值通常不高，属正常）。
- 真正的判断标准：YouTube 能不能流畅播 1080p、Claude 流式输出顺不顺。

## 诊断「慢」在哪一环

1. **只有某个网站慢、其他都快** → 该站问题，不是线路。
2. **全部都慢** → 看延迟命令结果，可能是线路或本地网络。
3. **晚高峰慢、白天快** → 本地宽带出国拥堵，换线路可缓解。
4. 关闭 IPv6、别同时开多个代理工具互相打架。

## 底层优化（自建节点时）

- 开启 **BBR** 拥塞控制，显著提升弱网下的带宽利用率。
- 选优质回程线路（AS9929 / CN2 等）。
- MTU 保持 1500。
