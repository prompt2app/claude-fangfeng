# 上下文与成本控制

> 原文地址：[https://claucc.net/articles/cc-07-context-cost](https://claucc.net/articles/cc-07-context-cost)　·　更多教程见 [claucc.net](https://claucc.net)

长时间、多任务地用 Claude Code，依然保持回答质量，同时控制用量。

## 一、上下文是什么、为什么会「变笨」

会话里的所有内容都在上下文里：你说的话、它读过的文件、命令输出、截图。上下文越长：

- 每一轮请求越慢、越贵；
- 早期的细节越容易被「冲淡」；
- 无关信息越多，越容易答偏。

所以管理上下文，本质是**只让有用的信息留在主对话里**。

## 二、几个关键命令

| 命令 | 作用 | 什么时候用 |
| --- | --- | --- |
| `/clear` | 清空当前会话 | 换一个完全不相关的任务时 |
| `/compact` | 把之前的内容压缩成摘要 | 同一任务做了很久、要继续时 |
| `--continue` / `--resume` | 恢复之前的会话 | 第二天接着做同一件事 |

经验：**一个任务一个会话**。做完一件事就 `/clear`，比在一个会话里做十件事效果好得多。

## 三、让主对话保持干净

- **大范围搜索交给子代理**（[第 04 篇](cc-04-subagents-skills.md)）：几百行搜索结果留在子代理里，主对话只拿结论。
- **不要整文件读大文件**：让它先 `grep` 定位，再读需要的那几十行。
- **长输出截断**：命令输出很长时，让它只看 `head` / `tail` 或过滤后的关键行。
- **截图要有目的**：每张截图都占上下文，验证完的截图不需要反复看。

## 四、规范写进文件，而不是对话

同样的要求每次在对话里说一遍，既费上下文又容易漏。应该：

- 项目约定 → `CLAUDE.md`；
- 个人习惯（语言、风格）→ 用户级的 `~/.claude/CLAUDE.md`；
- 固定流程 → Skill；
- 它犯过的错、你纠正过的做法 → 让它记进记忆或 `CLAUDE.md`。

## 五、减少返工就是最大的省

最费钱的不是读文件，是**做错了重来**。几个习惯：

- **先出方案**（[第 03 篇](cc-03-plan-first.md)）：方向对了再写；
- **说清楚是讨论还是执行**：避免把「这样行不行」当成「去改」；
- **小步提交、及时验证**：每一步都验证，错了只返工一小步；
- **给截图、给报错原文**：比描述准确，少走弯路。

## 六、模型选择

不同任务用不同的模型（`/model` 切换）：

- **复杂设计、疑难排查、大改动**：用最强的模型，一次做对比反复试更省；
- **简单修改、格式整理、批量机械操作**：可以用更快更便宜的模型；
- **子代理**：机械的搜索类任务可以用快模型，审查类任务用强模型。

## 七、一张自查表

做完一个任务前，过一遍：

- ☐ 这个会话是不是只做了一件事？要不要 `/clear`？
- ☐ 有没有在主对话里做了本该交给子代理的大搜索？
- ☐ 有没有反复交代同一条规则？该写进 `CLAUDE.md` 了。
- ☐ 改动有没有验证证据（编译 / 测试 / 截图）？
- ☐ 有没有需要沉淀的经验（Skill、记忆、文档）？
