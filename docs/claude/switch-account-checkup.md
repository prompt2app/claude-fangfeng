# 切号 / 登录前环境自检(通用)

> 原文地址：[https://claucc.net/articles/switch-account-checkup](https://claucc.net/articles/switch-account-checkup)　·　更多教程见 [claucc.net](https://claucc.net)

多开账号最容易翻车的一刻,就是**切号那几秒**:上一个号的环境还没退干净就登了下一个,等于亲手把两个号绑在一起。这份 60 秒自检适用于 TikTok、外贸店铺、社媒矩阵、AI 账号——**登录前跑一遍,比出事后补救便宜得多**。

> [!CAUTION]
> **顺序不能反:先验环境,再登号**。反过来做,万一环境有问题,这个号已经被记录了——而记录是撤不回的。

## 五项自检

#### 1. 出口 IP 是不是「本号专属」的那一条

打开 `api.ipify.org` 或 `ippure.com`,确认看到的 IP **就是分配给这个号的那一条**,不是上一个号的、也不是你日常那条。**这是最常见的翻车点**。

#### 2. IP 类型与风险分

类型应为 **Residential(住宅)**,风险分**绿色**。是机房(Datacenter)或风险分偏高,就别登了,先换 IP。

#### 3. 没有 DNS / WebRTC 泄露

泄露会让你的真实 IP 从旁路漏出去——前面做的隔离**会全部白费**。怎么测怎么根治见 [DNS / WebRTC 泄露检测](dns-leak-check.md)。

#### 4. 时区 / 地域与 IP 一致

IP 在美国、时区却是北京,是很明显的矛盾信号。用指纹浏览器的开「跟随 IP 匹配时区」;用原生 App / 命令行工具的**还得改系统时区**。

#### 5. 指纹环境对不对

确认你打开的是**这个号对应的那个浏览器环境**,不是随手开的另一个。环境和账号必须长期一一绑定。

| 项目 | 说明 |
| --- | --- |
| 出口 IP | 本号专属那一条 ✓ |
| IP 类型 | Residential 住宅 ✓ |
| 风险分 | 绿色 ✓ |
| DNS / WebRTC | 无泄露 ✓ |
| 时区 / 地域 | 与 IP 一致 ✓ |
| 指纹环境 | 本号专属 ✓ |

*图:这几项全绿,才可以登录操作*

## 不合格怎么办

| 检测结果 | 说明 | 怎么办 |
| --- | --- | --- |
| IP 是上一个号的 | 环境没切干净,**最危险的一种** | 切到本号的代理,重新验一遍再登 |
| 类型显示 Datacenter | 走的是机房 IP,不是住宅 | 确认代理配置对不对,或 [加群交流](https://claucc.net/contact) |
| 风险分偏高 / 红黄 | 这条 IP 已被标记或被滥用过 | 换一条**不同段**的干净 IP,别硬用 |
| 检测到 DNS / WebRTC 泄露 | 真实 IP 会漏出去 | 见 [泄露检测与根治](dns-leak-check.md),堵住再登 |
| 时区对不上 | 矛盾信号,风控会记一笔 | 打开跟随 IP 匹配时区,或改系统时区 |
| 代理检测不通过 | 指纹浏览器自己拨号不经过 clash | 开 TUN,见 [这一节](adspower-socks5-setup.md) |

## 把它变成习惯

- **每次切号都跑一遍**。熟练之后不到一分钟,但能挡住绝大多数关联事故。
- **每月抽查几个环境**。IP 的风险分会随时间变化,今天绿的下个月可能变黄。变差了就换一条,别硬用。
- **给每个号留一份环境档**。记下它对应的 IP、环境名、注册时间和用途,出问题时能快速定位是哪一层串了。
- **环境和账号长期绑死**。真实用户不会天天换城市换设备,别轮换。

> 还没把隔离环境配起来的,先看 [指纹浏览器 + 独享住宅 IP:多号隔离怎么做](fingerprint-browser-isolation.md)(整体思路)和 [AdsPower 配合独享 socks5](adspower-socks5-setup.md)(逐步操作)。注册 AI 账号前的自检见 [注册前环境自检](ip-quality-check.md)。
