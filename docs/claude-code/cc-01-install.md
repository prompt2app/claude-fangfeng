# 安装与第一个项目

> 原文地址：[https://claucc.net/articles/cc-01-install](https://claucc.net/articles/cc-01-install)　·　更多教程见 [claucc.net](https://claucc.net)

装好 Claude Code，在自己的项目里跑通第一个真实任务，并写好项目的 CLAUDE.md。

## 一、安装与启动

```bash
# 需要 Node.js 18+
npm install -g @anthropic-ai/claude-code

# 进入项目目录再启动：它以当前目录为工作区
cd ~/code/my-project
claude
```

第一次启动按提示登录即可。之后常用的几种启动方式：

| 命令 | 作用 |
| --- | --- |
| `claude` | 在当前目录开新会话 |
| `claude --continue` | 接着上一次会话继续 |
| `claude --resume` | 从历史会话列表里选一个恢复 |
| `claude -p "问题"` | 一次性问答，不进交互界面（适合脚本里调用） |

> 习惯：**永远在项目根目录启动**。它能看到的文件范围、读到的 `CLAUDE.md`，都以启动目录为准。

## 二、第一个任务：从小而具体的开始

别一上来就说「帮我重构整个项目」。第一个任务挑一个**小、具体、能验证**的：

```
登录接口在密码错误时返回 500，应该返回 401 和提示「用户名或密码错误」。
先找到相关代码给我看，确认后再改。
```

这句话里有三个要素：

- **现象**（返回 500）和**期望**（401 + 提示语）；
- **范围**（登录接口）；
- **节奏**（先找代码给我看，确认后再改）。

它会先搜索、读文件、说明原因，等你确认后才改，改完会告诉你改了哪里。

## 三、写好 CLAUDE.md：项目的「入职手册」

`CLAUDE.md` 放在项目根目录，每次启动都会自动读入。它是你和 AI 之间**长期有效的约定**，比每次在对话里交代可靠得多。

最快的起步方式：

```
/init
```

它会扫描项目，生成一份初稿。然后**一定要自己改**，补上这些它看不出来的东西：

```markdown
# CLAUDE.md

## 回答语言
默认简体中文。

## 构建与运行
- 构建：mvn clean package -DskipTests
- 启动：mvn spring-boot:run -pl app-start（端口 8080）
- 单测：mvn test -pl <模块> -Dtest=<类名>

## 代码约定
- Controller 统一返回 Result<T>，不要直接返回实体
- 新增 SQL 不要以分号结尾（Oracle 会报错）
- 前端静态资源改动后，页面模板里引用的版本号 +1

## 不要做的事
- 不要自动提交 / 推送代码，等我说「提交」
- 不要改 application-prod.yml
```

几个经验：

- **写「为什么」**：「不要以分号结尾（Oracle 会报错）」比「不要以分号结尾」更容易被正确执行。
- **写「反常识」的东西**：和框架默认做法不一致的约定，最值得写进去。
- **子目录也可以有 CLAUDE.md**：大仓库里各模块的特殊规则，放到模块自己的 `CLAUDE.md`。
- **保持更新**：每次它犯了同一类错误，就把规则补进去。

## 四、权限：它能动什么、什么时候问你

Claude Code 默认会在**改文件、执行命令前征求你的同意**。可以按需切换模式（`Shift+Tab` 循环切换）：

| 模式 | 适合 |
| --- | --- |
| 默认 | 刚开始用、对项目不熟、改动敏感 |
| 自动接受编辑 | 信任它改代码，但命令仍要确认 |
| Plan 模式 | 只读、只出方案，不改任何东西（[第 03 篇](cc-03-plan-first.md)细讲） |

常用的只读命令（`git status`、`ls`、`grep` 之类）可以在设置里加白名单，减少反复确认。

## 五、几个马上能用的小技巧

- `@文件路径`：直接把某个文件引用进对话。
- `! 命令`：自己执行一条 shell 命令，输出会进入对话（比如 `! git diff`）。
- `Esc`：打断它当前的操作；`Esc` 两次可以回到之前的消息重新来。
- 截图可以直接粘贴进对话：报错弹窗、页面样式问题，截图比描述准确得多。

## 本篇小结

装好之后，先做三件事：在项目根目录启动、`/init` 后手改 `CLAUDE.md`、用一个小 bug 跑通「找代码 → 确认 → 修改 → 验证」的完整一轮。
